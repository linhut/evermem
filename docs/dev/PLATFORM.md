# 恒忆（Evermem）通用知识库平台设计 v2（细化与评审版）

> 定位：恒忆不应针对每一种具体需求单独开发，而应构建一个**可供所有行动统一使用的通用知识库平台**，为其提供高效、可靠且可复用的经验支撑。
> 本文档是平台总纲与评审基准。v2 在 v1（八模块闭环）基础上：细化适用范围与边界、补齐关键环节的步骤/判断标准/风险点、明示核心假设与验证状态、给出逻辑自洽性检查结论与下一步安排。

---

## 一、建设目标（三个可验收目标）

1. **一次沉淀，处处复用**：任何行动（写作、命令、配置、决策、培训、项目推进……）中验证过的经验统一入库；任何会话、任何宿主、任何场景可召回。
2. **信任分级**：每条经验有明确生命周期状态与来源，检索按可信度排序，杜绝"凭印象编造"。
3. **零摩擦运转**：沉淀（收尾 add）与调用（动笔前 recall）嵌入既有工作流，单次操作成本趋近于零；积累靠机制自动产候选，不依赖人的自律。

## 二、适用范围与边界（细化）

### 2.1 覆盖
- **领域**：不限。机制不预设领域，按使用自然沉淀（当前集中在政务/公文/信息化项目）。
- **场景**：AI 会话内调用（注入+检索+回写）、会话外人工检索（Web/CLI）、跨宿主（WorkBuddy/Claude Code/DSH/CodeBuddy/Marvis）。
- **角色**：AI Agent（主消费者）、用户本人（策展/审核/查询）。

### 2.2 边界（明确不做什么）
- 不做通用文档管理系统（原文归 NAS/网盘/块库，平台只存提炼后的经验）。
- 不做对话全文库（会话 jsonl 是证据层，只供溯源，不参与常规检索）。
- 不做云端 SaaS；Git 远程**可选**（默认本地仓库，涉密内容绝不 push，见 6-R2）。
- 不收集隐私/敏感细节（去敏纪律，见 4.7-R2）。
- 不做"自动抽取直接入库"（自动产物只进候选区，人工转正）。

### 2.3 入库判例（进/不进清单）
| 进 | 不进 |
|----|------|
| 未来还会再遇到的做法/坑/事实（命令用法、工具兼容、流程模板、政策文号、环境约束） | 一次性信息（本次会议定了谁、文件传哪了） |
| 已验证（跑通/生效/被确认）的经验 | 未验证的想法（除非标 suspect） |
| 可去敏后仍有价值的方法论 | 纯个人信息、敏感细节（IP/密钥/涉密文件名） |
| 带 source 指针、可追溯到证据的经验 | 原文/全文（引用归引用，正文是经验） |

## 三、核心功能模块（八模块，闭环）

```
采集 → 萃炼 → 存储 → 治理 → 检索 → 注入 → 策展 → 反馈
                      └────── 闭环：反馈驱动治理 ──────┘
```

| # | 模块 | 职责 | 现有落地 |
|---|------|------|---------|
| 1 | 采集层 | 五通道进料（见 4.1） | mem.py add / harvest.py / ingest.py+块库 / evermem_mcp.py / knowledge_scan.py |
| 2 | 萃炼层 | 原始证据/长文 → 原子笔记 | 人工+AI 协作，AI 只产候选 |
| 3 | 存储层 | Markdown 权威 + 派生索引 + 证据 + 热层 | notes/ + index.json + events/ + MEMORY_HOT |
| 4 | 治理层 | 状态机、写前相似治理、候选池治理、热层周转 | 见 4.3（候选池治理为 v2 新增） |
| 5 | 检索层 | 多级级联 + 新近度 + 缓存 | mem.py recall |
| 6 | 注入层 | 四通道按成本分层 | 热层/MCP/skill+规则 |
| 7 | 策展层 | 检索、审核、热层管理 | Web 六视图 + CLI |
| 8 | 反馈层 | 命中统计、召回回归、suspect 化、月度回顾 | stats / bench_verify |

## 四、关键环节：步骤、判断标准、风险点

### 4.1 采集（五通道 SOP）

| 通道 | 触发 | 步骤 | 产物去向 | 判断标准 |
|------|------|------|---------|---------|
| 会话收割 | 会话收尾/每周 | 读宿主落盘 jsonl → 抽取高价值段（成功配方/失败原因）→ 生成候选 | **候选**（staged） | 自动产物不得直接 active；含系统注入噪声的段落丢弃 |
| 文档导入提炼 | 按需（新编文档任务涉及） | 定位块库 → 读关键块 → 提炼（人工+AI） | active | source 指针必须；方法论文本必须 |
| 手动 add | 任务收尾纪律 | 三问（见 4.2）→ 写笔记 → reindex | active | 只写已验证 |
| MCP/API 写入 | 其他宿主任务收尾 | mem_record → 写前相似治理（见 4.3） | 候选或 active | 相似≥18 分必须提示替代/合并 |
| 扫描发现 | 周期 knowledge_scan | 生成主题/失败模式索引与报告 | 参考层（不进 notes） | 不自动入库 |

**风险 R1 收割噪声**：历史会话用户消息含大量系统注入，直接进库会污染信噪比。
→ 缓解：一律 staged + 人工转正；抽取时按"可见文本+工具结果"双重过滤。

### 4.2 萃炼判断标准（入库三问 + 原子性）
写任何一条笔记前过三问：
1. **可复用性**：未来 3 个月还会遇到同类任务吗？（否 → 不写）
2. **已验证**：结论真正跑通/生效/被确认过吗？（否 → 标 suspect 或先验证）
3. **可去敏**：去掉敏感细节（IP/密钥/人名/涉密文件名）后还有价值吗？（否 → 只写法论层）
原子性：一条笔记一个经验；frontmatter 含 id/type/status/title/tags/env/source/created。

### 4.3 治理（状态机转换条件 + 候选池治理）
| 转换 | 触发条件 | 执行 |
|------|---------|------|
| staged → active | 人工审核通过（结构完整+已验证+去敏+有 source） | Web 候选页一键转正 |
| active → suspect | 使用中发现错误 / 冲突检测高分 / 月度回顾质疑 | 标 suspect，默认检索隐身 |
| active → superseded | 新笔记写前相似治理命中高分且人工确认替代 | 新笔记 active，旧笔记 superseded，不删历史 |
| staged 清理（v2 新增） | 超过 30 天未审核 → 待清理观察；60 天未动 → 归档（不删，降级目录） | 防止候选池无限膨胀 |
| 热层周转 | token 预算硬顶（当前 20）；pinned 人工保；auto-fill 算法补足 | 有进有出；月度抽查 auto-fill 质量 |

**AI + 人工双审核（v2.1）**：staged→active 前先过 AI 审核层——`mem.py candidates review` 本地启发式评分（相似度 / 占位符噪声 / 失败收敛度 / 信息量，0-100 分：promote≥70 / keep 45-69 / archive<45），Web 候选页显示 AI 徽章（分数+建议+理由+疑似重复目标）；**人工按钮（转正/存疑/归档）始终保留为终审**。可选 LLM 精审：配置 `PMEM_AI_REVIEW` 后 review --llm，涉密环境保持关闭。

**风险 R3 候选池膨胀**：收割自动化后若审核滞后，候选积压会重新造成信噪比问题。
→ 缓解：候选上限 + 30/60 天 TTL + Web 批量审核界面（一次勾选多条转正/归档）。

### 4.4 检索（级联触发 + 响应契约）
- 触发选择：意图签名（查询匹配已知任务模板）→ 失败指纹（含错误信息原文）→ **BM25（默认路径）** → 链接扩展（命中笔记引用展开）→ 向量（量 >1000 启用，引入信号见 5.3）。
- 排序：BM25 分数 × 新近度衰减（180 天线性）；召回门槛：特异性词元占比 ≥34%。
- 契约：命中给 标题+摘要+分数+source；**无命中明确说无命中，并提示换词建议**，禁编造。

**风险 R5 检索退化**：语料增长后常见词区分度下降、噪声命中上升。
→ 缓解：200 条时跑基准回归（bench_verify 扩展一组标准查询，对比命中与排序）；top 命中分数中位数持续偏低 = 引入向量或调阈值。

### 4.5 注入（四通道选择标准）
- **热层**（常驻，数百 token）：只放"不检索也必须看到"的硬知识（救命命令/环境限制/核心约束）。
- **MCP**（按需，触发才用）：执行中随时查细节。
- **skill 纪律 + 用户规则**（场景强制）：特定类型任务（如公文/方案）动笔前必 recall——用规则机制钉住。
- **Web/CLI**（人工）：策展与查询。

**风险 R6 纪律失效**：某宿主未注入纪律时 recall 被跳过。
→ 缓解：热层兜底（核心知识不依赖检索）；无命中明示纪律本身可被审计（见 4.6 反馈）。

### 4.6 反馈（指标定义 + 月度动作）
| 指标 | 定义 | 触发动作 |
|------|------|---------|
| 库容与分布 | stats：条数/type/tags 分布 | 容量与领域健康检查 |
| 命中救火榜 | recall 结果统计：被回看最多的笔记 | 高分笔记标 hot / 检查时效 |
| 候选转正率 | 转正数 / 新候选数 | 转正率 <30% → 降收割力度或改抽取规则 |
| 热层周转 | 进/出记录 | 月度"有进有出"评审 |
| 无命中占比 | recall 无命中次数 / 总次数 | 偏高 → 提示补笔记或换词 |

### 4.7 去敏纪律（入库硬规则）
正文禁止：密钥/令牌、内网 IP、身份证号/手机号、涉密文件名全称、单位内部敏感口径；需要时用 XXX 占位。文件层：.memory 笔记进 Git 前自查；涉密内容一律只留方法论。

## 六、逻辑自洽性检查（结论）

**自洽成立**：笔记唯一权威 ↔ 索引/热层可重建；五通道进料 ↔ staged 兜底信噪比；级联检索 ↔ 无命中契约；注入分层 ↔ 成本分层。

**需调整的 4 处（v2 已吸收）**：
1. "零摩擦" 与 "文档提炼重流程" 并存 → 文档提炼明确定位为**按需通道**（4.1），非日常路径。
2. "自动产物只进候选" 缺候选治理 → 新增候选池上限/TTL/批量审核（4.3）。
3. "本地零云端" 与 Git 远程未界定 → 明确 Git 远程可选、涉密绝不 push（2.2/R2），并纳入假设 A8 决策。
4. "多宿主一致性 = 单一写者" 与现状 MCP 直写不一致 → 明确当前兜底为"单机顺序写"，远期收敛到单一写者（A6）。

**待验证清单**：A1 保留期、A2/A3 检索与热层质量、DSH 热层注入目标文件、MCP 当前会话是否注入。
