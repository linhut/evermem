# 界面一级模块清单

侧栏每个入口对应一个一级模块，`data-view` ↔ `VIEWS` 键 ↔ `render()` 分支 ↔ `HTML()` 模板一一对应。
结构改动后跑 `python scripts/frontend_smoke.py`，第六项会做这四方的交叉校验。

## 当前模块

| 分组 | 模块 | VIEW 键 | 内容 |
|---|---|---|---|
| 记忆 | 记忆浏览 | `browse` | 列表 + 详情（双列，不套卡） |
| 记忆 | 候选审核 | `triage` | staged 候选列表 + 转正/存疑 |
| 记忆 | 数据导入 | `import` | ① 文档导入 ② 其他记忆导入（分段控件切换） |
| 系统 | 核心经验 | `hot` | 热层条目（上限 20，有进有出） |
| 系统 | 统计诊断 | `stats` | 统计、分布、健康度 |
| 系统 | 接入设置 | `integ` | ① 技能安装 ② MCP 工具接入 ③ 开机启动 ④ 兼容说明 |
| 系统 | 数据与维护 | `maint` | ① 数据位置 ② 核心经验同步 ③ 经验沉淀 |
| 系统 | 数据备份 | `backup` | 交给渠道模块 `channel.js`，`index.js` 只做路由 |
| 系统 | 版本与更新 | `update` | ① 更新检查 ② 更新源 |

## 什么算一级模块

- **用户会单独为它点进来**，而不是"打开别的页面顺带看一眼"。
- **模块名能覆盖全部卡片**。出现"这张卡跟模块名没关系"就是拆分信号。
- **一个模块超过 5 张卡且分属两类事**就该拆。

反面案例：「接入设置」一度堆到 8 张卡，里面混着三类事——对外接入（技能、MCP）、本机数据（数据位置、同步、沉淀）、软件本体（开机启动、兼容说明、版本更新）。
现已拆出「数据与维护」与「版本与更新」，接入设置只留对外接入 + 本机运行方式。

## 父模块不要套同名卡

页头已经显示模块名，内容区直接分卡即可。再套一张与模块同名的卡，就变成
「页头一层 + 卡片标题一层 + 卡内一层」的三层嵌套，且父模块被降级成与自己的子卡并列。
这个坑在「数据导入」上踩过，独立成模块的页面一律不再套同名父卡。

## 新增模块的落地顺序

1. `web/index.html`：侧栏加按钮（`data-view` + 图标 + `data-i18n` 文案）。
2. `web/index.js`：`VIEWS` 加键 → `render()` 加分支 → 写 `<name>HTML()` 模板 → 写 `load<Name>()`。
3. `web/i18n.js`：模块名与新卡标题补英文映射（侧栏文案漏了会在英文模式下残留中文）。
4. 跑校验：`scripts/frontend_smoke.py` 与 `scripts/check_all.py`。
