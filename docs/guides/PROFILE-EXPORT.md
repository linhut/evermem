# 使用画像导出（LLM 对话级记忆导出）

## 它解决什么问题

恒忆管的是**经验**（踩坑、配方、事实），画像管的是**人**（我是谁、我怎么要求你）。
两者的差别决定了导出方式不同：

| | 恒忆笔记 | 使用画像 |
|---|---|---|
| 内容 | 某任务怎么做成 | 我长期不变的指令与偏好 |
| 粒度 | 一篇一篇 | 一行一条 |
| 消费方 | 检索时按需召回 | 新会话开头整体贴入 |
| 生成 | 本地收割 + 评审 | 本地草稿 + LLM 归类补全 |

画像必须短（几十行以内）、必须真（每条有依据）、必须用原话（改写后就不是你的要求了）。

## 三条可行路径

### 1. 会话内导出（零准备）

把 `templates/usage-profile.prompt.md` 的 A 段整段发给任意 LLM。
优点：随时可用。缺点：依赖该工具自己的长期记忆，换个工具内容就变了；且模型倾向把推测写成事实。

### 2. 恒忆本地草稿 → LLM 补全（推荐）

```bash
python mem.py profile --limit 5 --out 画像-草稿.md
```

`mem.py profile` 只做两件事：

- 从 **active 笔记**里按分类关键词挑候选（标签权重 3、标题权重 1，正文片段不参与——泛词太多会失去区分度）
- 按 `[YYYY-MM-DD] - 条目内容` 排好，附**覆盖率说明**，明确列出本地无依据的维度

然后把草稿连同 B 段提示词一起交给 LLM。LLM 只做归类、去重、补 `[待确认]` 项，**不改原话**。

### 3. 纯手写（最准，最慢）

直接按同样格式写一份，存进笔记库（type=fact，tags 带 偏好/身份），之后每次 `mem.py profile` 都会带出来。

## 为什么必须有"覆盖率说明"

画像最常见的失败不是漏了几条，而是**看起来很全**——模型把推测条也写成确定条，你带去新工具后
一直被错误的前提带着走。所以模板强制要求：

- 代码块之后单独一段说明未覆盖/存疑的维度；
- 补全的条目必须标 `[待确认]`；
- 本地无依据的分类直接说"无依据"，而不是拿笔记凑数。

## 回灌：让画像越用越准

画像不是一次性的。每次发现某条要求反复出现，就写成 fact 笔记：

```bash
python mem.py add --type fact \
  --title "指令：文档类任务动笔前先查记忆" \
  --tags 指令,纪律,流程 \
  --body "接到编写/优化/生成类任务，动笔前先 mem.py recall 一次……"
```

下次 `mem.py profile` 会自动把它挑进「指令」分类，形成正向循环。

## 与热层的分工

- **热层**（`mem.py hot`）：每次会话自动携带，装的是能救命的经验，有 token 预算硬顶。
- **画像**：手动带去新工具，装的是人设与长期要求，不受热层预算约束，也不该挤进热层。

两者不合并——合并的结果是热层被人设稀释，画像被经验撑爆。
