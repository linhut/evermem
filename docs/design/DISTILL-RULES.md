# 恒忆记忆提取规范（DISTILL-RULES）

> 定位：恒忆的初衷是把会话中的"昂贵试错"沉淀为**可跨会话复用的经验**，而不是保存对话记录。
> 因此提取的本质是 **蒸馏**：对原始内容做归纳、概括、抽象，提炼出通用经验或规律。
> **禁止把对话原文、命令日志、文档片段未经处理直接作为记忆保存。**

---

## 一、核心判定标准（一条合格记忆的四个硬指标）

| 标准 | 含义 | 自问 |
|------|------|------|
| **通用性** | 脱离本次会话/路径/时间，未来同类场景仍适用 | "换个项目/换个时间，这条还有用吗？" |
| **抽象度** | 上升为"规律/方法/原则"，而非"我做了什么" | "这是在描述动作，还是在总结规律？" |
| **原子性** | 一条记忆只讲一件事，不堆叠 | "是不是拆成两条更清楚？" |
| **已验证** | 结论真正跑通/生效/被确认过 | "这是验证过的，还是我猜的？" |

四者缺一即不达标；未验证但重要的内容，只能标 `suspect` 进候选，不得标 `active`。

## 二、结构标准（三类笔记的标准写法）

**procedure（怎么做，核心资产）**：
```
背景 → 步骤/框架 → 关键要点（量化、踩坑） → 适用范围与例外
```

**lesson（别怎么做）**：
```
问题现象 → 无效做法及原因 → 已验证的正确做法 → 适用范围
```

**fact（事实/环境约束）**：
```
客观事实/约束 → 对行动的影响 → 边界
```

frontmatter 必须含：`id / type / status / title / tags / env / source / created`；`source` 指向证据，`title` 用可检索关键词。

## 三、禁止事项（违反即不合格，直接退回或归档）

1. **禁止原文转录**：对话原文、命令日志、失败输出、文档片段原样塞进正文——必须归纳。
2. **禁止一次性信息**：本次会议定了谁、文件传到了哪个目录、今天做了什么——不可复用，不入库。
3. **禁止未验证内容**：推测、想法、未跑通的做法——除非标 `suspect`。
4. **禁止敏感细节**：密钥、内网 IP、身份证号、手机号、涉密文件名全称——去敏或 XXX 占位。
5. **禁止工具操作碎片**：单条工具调用的"成功配方"（如"成功配方：git commit 成功"）不是知识，不入库。
6. **禁止重复**：与已有 active 笔记高度相似（评分≥25）的，做替代/合并而非新增。
7. **禁止模糊标题**：标题不含可检索关键词、无法让未来检索命中的，退回重写。

## 四、示例对照

### ❌ 反例 1：原文转录（工具碎片）
```markdown
title: [候选] 成功配方：Bash:git add . && git commit -m "xx" && git push
正文：工具：Bash / 命令签名：Bash:git add ... / 首次命令：git add ...
     输出片段：...
```
问题：这是"做了什么"的记录，不是"规律"，且含一次性路径，不可复用。

### ✅ 正例 1：抽象为规则（lesson）
```markdown
title: 自建 HTTP 客户端返回字符串，类型判断别用 isinstance(dict)
正文：自封装的 api() 返回 r.read().decode() 的字符串（未 json.loads），
    后续 isinstance(body, dict) 恒为 False，清理逻辑永不执行。
    正确做法：网络/文件读到的 JSON 文本是 str，先 loads 再取字段；
    最稳是让 api() 直接返回解析后的 dict。
适用范围：任何自写 HTTP 客户端 / 文件解析场景。
```

### ❌ 反例 2：一次性信息
> "今天把现场调研报告传到了调研目录，负责人下午要看"

### ✅ 正例 2：可复用经验（procedure）
> "某政务信息化项目方案编制要点"——从《某系统初步设计 V3》提炼：章节结构（必要性论证套路/可行性四方面/建设周期模板）+ 采购模式（市级统筹、两级费用分摊、合同分签）。

### ❌ 反例 3：敏感细节
> "服务器 172.16.1.100 的 root 密码是 admin123"

### ✅ 正例 3：去敏后
> "政务云服务器禁止使用弱口令，管理端口仅允许堡垒机登录（见安全自查清单）"

## 五、与现有机制的衔接

1. **入库三问**（mem.py 纪律）：可复用性 / 已验证 / 可去敏 —— 即本规范"四个硬指标"的落地版。
2. **多角色评审**：价值官（通用性+抽象度）、质量官（结构+标题）、合规官（去敏）、新颖官（重复）——本规范的自动把关。
3. **自动收割**：收割器只产出"候选碎片"，**不直接入库**；procedure 成功配方不自动转正（对应禁止第 5 条）。
4. **AI 提炼**（如"提炼一下这次会话"）：按本规范归纳成 procedure/lesson/fact，而非复制原文。
