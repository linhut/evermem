# RECIPES.md — 配方管理规范

> 恒忆（Evermem）知识库的"配方"治理权威文档。版本 1.0（2026-09-29）。
> 背景与要点速览见笔记 `20260929-2325-182`；工具实现见 `recipes.py`。

## 1. 目标与适用范围

本规范解决一对矛盾的平衡：**配方隔离**（避免不同项目互相干扰）与**配方共享**（跨项目复用且不污染）。适用于恒忆仓库内一切"配方"类知识——即**可复用的知识条目或配置组合**：程序配方（procedure）、检查清单、规则集、模板、工具调用方式等。事实（fact）与一次性教训（lesson）不强制纳入，但允许标注 scope 以便检索。

设计原则：不动现有 `mem.py` 核心；所有扩展字段对现有解析器宽容（未知 frontmatter 字段被忽略）；索引仍可从 Markdown 幂等重建。

## 2. 配方元数据 schema（frontmatter）

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `id` | 是 | 存量格式 `YYYYMMDD-HHMM-NNN` 或新格式 `scope/name@version` | 存量笔记不改 id |
| `scope` | 新配方必填 | `core:*` / `org:*` / `project:*` / `session:*` | 所有权命名空间，缺省按 L2 项目层处理 |
| `priority` | 否 | 数字，默认 50 | 同层冲突时小者优先 |
| `depends` | 否 | `[scope/name@semver]` | 声明式依赖 + 语义化版本区间 |
| `overrides` | 否 | `[目标配方 id]` | 显式覆盖链，禁止隐式覆盖 |
| `version` | 新配方推荐 | `MAJOR.MINOR.PATCH` | 语义化版本 |
| `env` | 否 | 宿主标识 | 环境门控，不匹配自动停用 |
| `status` | 是 | 复用恒忆状态机 | staged/active/suspect/superseded/archived |

示例：

```yaml
---
id: org:yjxt/emergency-comm@1.0.0
type: procedure
status: active
title: 应急通信装备配置与提示函要点
scope: org:yjxt
priority: 50
depends: [core:gongwen/quality-checklist@~1.0]
overrides: null
env: 通用
version: 1.0.0
created: 2026-09-27
---
```

## 3. 四层作用域模型

| 层 | 命名空间 | 内容 | 隔离规则 |
|---|---|---|---|
| L0 核心层 | `core:*` | 普适基线：GB/T 9704、通用质检清单、语言约定 | 只读，不可被覆盖，只能被显式 override 引用 |
| L1 组织层 | `org:*` | 部门业务配方：应急（`org:yjxt`）、民宗委（`org:mzw`）等 | 组织内共享，版本化发布，消费方锁版本 |
| L2 项目层 | `project:*` | 项目专属：运动会保障（`project:games`）、恒忆开发（`project:evermem`）等 | 项目自有 + overlay 覆盖 + 锁文件 |
| L3 会话层 | `session:*` | 当次会话临时产物 | 可引用上层，禁止被任何层引用 |

**引用方向只许向上，杜绝循环依赖**：L2 可引用 L1/L0，L3 可引用其上所有层；任何层不得引用同层或下层（同层引用属于"播种/合并"流程，需显式记录）。

## 4. 命名与版本规则

- 命名：`scope/name@version`。`scope` 即所有权，跨命名空间同名不算冲突；同命名空间同名即冲突。
- 版本：语义化版本。`MAJOR` 变更 = 破坏性更新（消费方必须显式升级，默认不自动跟随）；`MINOR` = 新增且向后兼容；`PATCH` = 修复。
- **不可变基线**：被引用的版本一经发布只读，禁止事后修改；修改必须升版本。
- **共享只有两种合法形态**：
  - 引用（reference）：指向共享配方锁定版本，默认形态；
  - 播种（fork）：复制后脱钩，必须保留 `parent` 指针记录分叉来源。
  - 直接"复制粘贴"共享配方视为非法——要么引用，要么走播种流程。

## 5. 覆盖规则（防打架红线）

1. **禁止隐式覆盖**：项目内出现与共享配方同名/同用途条目时，必须显式声明 `overrides: [目标配方 id]`，形成可追溯覆盖链。
2. **求值顺序固定**：会话 > 项目 > 组织 > 核心（就近优先，等同 PATH / CSS 特异性）。
3. 跨层覆盖必须声明；**同层冲突一律挂起，等人工仲裁**，不允许运行时悄悄生效。
4. 覆盖只影响声明它的项目，不反向污染共享层。

## 6. 六类冲突与仲裁流程

| 冲突类型 | 触发场景 | 处理方式 |
|---|---|---|
| 命名冲突 | 同命名空间同名 | 自动拒装（入库 fail fast） |
| 版本区间冲突 | 引用方依赖区间不兼容 | 自动求交；空交集转人工 |
| 覆盖冲突 | 多配方显式覆盖同一目标 | 按 priority 裁决；同级挂起 |
| 契约冲突 | 被引用方 MAJOR 升级改字段 | 升级强制检查引用面，破坏性变更必通知 |
| 生命周期冲突 | 被引用方 superseded/archived | 反向引用图自动通知全部消费方 |
| 语义冲突 | 同场景给出不同规则 | 运行时并列返回 + 标注 trust，必须人工 ADR |

**流程**：检测（入库 / 发布 / 加载 / 升级四时机 + 定期漂移扫描）→ 归类分级 → 影响面分析（反向引用图）→ 仲裁（自动规则处理约 70%，人工 ADR 处理约 30%）→ ADR 留档 + 广播影响面 + 消费方冒烟验证。

**ADR 笔记要求**：记录决策、备选方案、失败边界、裁决日期；永久留档，不可删除。

## 7. 工具与落地

- 扫描/解析：`python recipes.py scan`（盘点分层、同名检测、隐式覆盖告警，有 P0 冲突时退出码非 0）
- 求值顺序：`python recipes.py resolve <scope-key>`（演示给定项目 scope 的生效优先级链）
- 锁文件：`python recipes.py lock [--project <name>]`（生成/刷新 `.recipe-lock.json`，记录引用依赖快照）

锁文件 `.recipe-lock.json` 不进 Git 可重新生成；`recipes.py` 与规范文档进 Git。

## 8. 失败边界（诚实声明）

- **版本锁定 → 知识僵化**：无人主动升级时共享配方会过时。缓解：定期漂移扫描 + superseded 通知；但"无人升级"是组织问题，机制只能减轻。
- **仲裁依赖人**：若语义冲突占比超 30%，说明分层/命名规范没做好，回头查第 3、4 节，不要加更多规则。
- **元数据通胀**：字段就上表这些，新增字段需审核，避免没人写。
- **单人场景**：可砍到最简——命名空间 + frontmatter + 同名检测三条即够，锁文件可省略。

## 9. 落地路线（M0-M3）

- M0 盘点建模：现有配方打标归类，定命名规范 —— 已由 `recipes.py scan` 支持
- M1 隔离生效：同名检测 + 求值顺序 + 禁隐式覆盖告警 —— 已由 `recipes.py scan/resolve` 支持
- M2 共享通道：发布/引用/锁文件 —— 已由 `recipes.py lock` 支持（发布 = 升版本 + 不可变快照，人工执行）
- M3 冲突治理：反向引用图 + ADR 流程 —— 流程已定义（第 6 节），自动化为后续迭代项
