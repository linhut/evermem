按"最小化重复试错成本"这一唯一目标重构后的架构原则。

一、目标校准。系统存在的理由只有一个：减少重复试错。所有设计用"节省的时间 − 维护成本"衡量。维护成本是主要杀手：一个每周要花一小时整理、每月只省三十分钟的系统是负收益。因此维护成本必须趋近于零，且系统失效时不能碍事。

二、最大风险在"用"这一环。存储与采集再好，若模型不在行动前检索，一切归零。在钩子被禁用的宿主里，靠 skill 提醒模型主动 recall 是唯一手段，但它依赖模型自觉，是单点故障。

三、解法：热层走宿主必读通道。把最高价值的二十条以内记忆同步进宿主每次会话必定读取的文件（如项目 MEMORY.md），不依赖任何检索动作。这样即使模型从不 recall，高价值经验也一定生效。其余长尾记忆走检索，冷层证据只用于溯源。分层依据是"被使用的确定性"而非访问频率。

四、价值聚焦优先于覆盖面。真正省时间的是命令、工具、环境配方这类窄域硬知识：稳定、可复用、错了代价高。一次性的项目细节价值低。应先做透这个窄域，不要一开始就做通用知识库。

五、自动化要让位于信噪比。自动收割若产出大量噪声，人工确认成本会吃掉全部收益。宁可少生成候选，也不要让人天天筛垃圾。信噪比不足时先调识别规则，不要继续扩量。

六、治理层防止腐烂。每条记忆带 trust 与 status；复用成功升权、失败降权转 suspect；被推翻的标 superseded 不删除；长期未命中的自动归档。索引随时可从笔记重建，笔记是唯一权威。
