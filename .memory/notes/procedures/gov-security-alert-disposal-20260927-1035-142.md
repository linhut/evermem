从真实政务安全通报"政务网络安全隐患预警（2023 第 6 号）"及各单位自查整改报表提炼。政务网常见漏洞预警的处置闭环。

## 预警处置闭环（四步）

下发预警（含 CVE 清单与风险等级说明）→ 责任单位/系统厂商限期自查整改 → 填报自查结果表 → 反馈上级部门（实例要求 2023-04-07 前反馈）。

## 自查整改六项（通用检查清单）

1. 是否存在**弱口令和规律口令**
2. 是否清理服务器遗留的**资产信息、账号密码及个人敏感信息**
3. 是否**关闭互联网 Web 后台管理页面、测试站点及测试服务器**
4. 管理端口是否**严格限制只允许通过堡垒机登录**
5. 是否**严格限制服务器上网行为**
6. 对应漏洞是否存在、是否完成修复（实例漏洞：Outlook 权限提升 CVE-2023-23397、MinIO 信息泄露、Spring Framework 身份认证绕过 CVE-2023-20860）

## 自查台账要素（报表模板）

系统名称（一级）/子系统名称（二级）/服务器名称/IP 地址/逐项自查状态/备注（虚拟 IP、已停机等特殊情况）/漏洞修复情况。
- 资产梳理时可区分"虚拟 IP 非主机资产""已停机"等，避免误报
- 涉及供应商系统时由各系统厂商自查（"请部室所属应用系统厂商对各自负责的服务器与系统进行自查整改"）

## 复用要点

- 政务安全预警通报通常带"第 N 号"编号与风险等级、CVE 编号，处置要求明确截止日期与反馈路径
- 弱口令、测试站点暴露、非堡垒机直连是政务网复检最高频扣分项，做安全自查时优先查这三项

## 例外与边界

- 具体 CVE 会过期，引用时以最新预警为准；本清单是处置框架，不是漏洞库
- IP、系统名等敏感信息不要原样写入笔记正文（本文只留结构）
