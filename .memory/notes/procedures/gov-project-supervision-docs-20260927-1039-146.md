从市政府综合指挥中心二期项目监理文档（湖南天道信息技术咨询有限公司编制）提炼。政务信息化项目委托监理时的文档体系：规划是纲领、细则是操作、日志是记录。

## 监理规划（纲领性文件，项目启动时编）

- 编写说明 / 工程概述
- 监理目标、范围及任务：
  - 监理任务内容
  - 监理服务需求分项：**总体需求 / 目标需求 / 范围需求 / 内容需求 / 任务需求 / 团队及人员需求 / 其他需求**
- 监理工作目标 / 监理工作范围 / 监理职责
- **项目进行各阶段监理任务**（按阶段展开）
- 监理依据与监理设施

## 监理细则（操作性文件，对规划的细化）

- 工程概况：项目名称 / 建设目标 / 需求分析 / 工期 / **项目建设三方**（建设方/监理方/承建方）
- 监理阶段、范围和目标
- **工程特点难点**（特点分析 + 难点分析分列）
- 工程执行的标准、法规（依据清单）
- 监理工作内容及流程：监理工作总程序 → **招投标阶段监理流程 → 设计阶段监理流程 → 工程开工程序**（按阶段给流程图）

## 配套记录（过程留痕三件套）

- 监理日志（J06）：施工期逐日记录（现场情况/问题/协调/验收），是结算与争议定责依据
- 监理例会纪要、旁站记录、报审表回执（进度/变更/款支付）

## 复用要点

- 政务项目"三控三管一协调"（进度/质量/投资控制，合同/信息/安全管理，组织协调）体现在规划+细则两层
- 细则必须落到"阶段流程"，评审看的是"招投标→设计→开工→施工→验收"每阶段有没有监理动作
- 监理日志这类过程文档平时不起眼，验收和审计时是硬证据，政务项目务必留全

## 例外与边界

- 监理机构需有资质（信息化监理资质/工程咨询资质），招标文件会写明
- 细则深度取决于项目规模，纯软件项目可简化，含机房/线路施工项目必须全
