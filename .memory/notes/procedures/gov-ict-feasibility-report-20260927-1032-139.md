从长沙市应急指挥中心二期可研报告（华信咨询设计院编制）提炼。政务信息化项目可研的成熟结构，与初设方案（笔记 117）配套使用：可研先行、初设细化。

## 章节结构

1. 项目概述：项目名称 / 建设单位和负责人 / 编制单位 / 编制依据（**政策依据、技术依据、估算依据三层分列**）/ 项目概况（背景、目标、规模、内容、周期）/ 总投资及资金来源 / 主要结论与建议
2. 项目建设单位概况：**牵头单位、建设单位、共建单位、实施机构、使用单位**五类单位及其职能分别界定
3. 项目现状及需求分析：现状及问题分析 → 需求分析（用户/业务/硬件/建设）→ **项目建设必要性分析 → 安全需求分析**
4. 总体建设方案（设计原则/目标/任务/系统架构）/ 投资估算 / 资金来源 / 效益与风险评价

## 关键写作经验

- 编制依据必须拆"政策/技术/估算"三层，政策层引国家+省+市文件，估算层引计价依据——评审专家会逐条核
- 五类单位（牵头/建设/共建/实施/使用）分开写，避免权责不清；信息化项目常见"多头管理"评审问题就出在这
- 必要性分析放"现状问题"之后顺势引出，与初设的"国家战略→本地机遇"套路（笔记 117）互补
- 需求分析要量化：带宽/链路数量/会场数量/终端数量（如各级 MCU 带宽、会场环境要求）
- 编制单位通常是咨询设计院（华信等），文件命名带编制日期（如 二○二○年七月），版本管理很重要

## 例外与边界

- 可研侧重"能不能建、花多少钱、谁来建"，技术细节浅于初设；不要两本混写
- 安全需求分析在政务项目中已成必写项（等保+密码应用，见笔记 137）
