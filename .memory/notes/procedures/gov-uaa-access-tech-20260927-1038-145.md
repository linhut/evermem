从"政务人员统一认证业务接入技术指引"提炼。政务业务系统接入政府侧统一身份认证平台（数据局统一认证）的对接流程与原理。

## 架构三件套（名词先讲清）

1. **政务认证系统**：提供认证、人员、机构、标签服务 + 账号/权限管理
2. **准入网关**：站点与服务访问控制，提供身份接入、设备鉴权、按应用授权的资源准入
3. **API 网关**：接口生命周期管理（发布/维护/订阅），统一鉴权调用标准，应用间接口调用的鉴权标准

## 对接目标（两类场景）

- PC 端：业务系统用统一认证平台登录，通过认证平台获取用户基本信息、组织架构，实现**单点登录**
- 移动端：接入**政务微信工作台**（政务微信也接统一认证）

## 接入流程（测试/生产两段）

- 测试环境：加入对接支撑群 → 群文件下载**应用接入申请表 + 站点接入申请表** → 填写并发统一认证负责人 → 配合测试联调。注：要实现单点登录须**站点表+应用表双填**，否则只填应用表
- 生产环境：业务系统在**网关发布应用 + 订阅接口服务**，按数据局规定流程申请

## 登录原理（PC 流程，写对接方案必述）

1. 用户访问接入业务系统 → 请求先过智能网关 → 网关查浏览器 cookie 登录态
2. 无登录态/失效 → 跳转政务认证登录页（政务微信扫码 或 认证账号密码）
3. 登录完成网关放行，并在业务系统请求头带 **Userid + 鉴权信息**
4. 业务系统**验证签名正确性** → 通过后获取用户信息

政务微信工作台路径：网关与政务微信做 **OAuth2.0** 授权获取用户信息。

## 复用要点

- 业务系统侧核心工作：接入网关（发布/订阅）+ 请求头取 Userid + **签名验签**（不验签等于没接入）
- 政务场景对接常分"站点接入"与"应用接入"两层申请，写实施方案时按两层列
- 申请表类附件是政务对接常见产物（呼叫系统/融合通信系统各有接入申请表），对接时先索取表单模板

## 例外与边界

- 本文为某市政务侧统一认证；各地平台（如省级统一认证）流程与表单不同，套用结构、替换入口
- 涉及政务微信、数据局流程，涉密/敏感信息不写入笔记正文
